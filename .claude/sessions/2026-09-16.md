  external Redis up and the env values below.
- After merging, on the dev machine: start `~/redis-compose/docker-compose.yml`;
  in `backend/.env` set `COMPOSE_HORIZON_PORT=8001`; in `backend/project/.env` set
  `QUEUE_CONNECTION=redis`, `CACHE_STORE=redis`, `SESSION_DRIVER=redis`,
  `REDIS_HOST=host.docker.internal`, `HORIZON_URL=http://localhost:8001`,
  `REDIS_QUEUE_RETRY_AFTER=150`; then `docker compose build nginx && docker compose
  up -d` and check `docker compose exec app pm2 list` shows `horizon` online and
  http://localhost:8001/horizon opens.

## Environment gotchas
- Backend tests: host `php` must be 8.3+; the suite runs on SQLite in memory and
  reads nothing from `.env`.
- Queue workers load config once at start. After a config change run
  `docker compose exec app php artisan horizon:terminate` (pm2 relaunches Horizon),
  or the workers keep the old config and jobs fail. A removed pm2 process lingers
  until the container restarts.
- A running `next dev` can keep serving a stale stylesheet after a `globals.css`
  edit; restart it.
- The auto-mode classifier sometimes denies `gh pr merge` or `pm2 delete`; retry or
  run by hand.
- PSGC and country reference data (`backend/project/database/seeders/data/addresses/`)
  is Philippine geographic data kept by decision; "citizenship" is a generic field.
