# QA — user registration and profile

**Baseline:** develop @ `1111111`. Regenerate this plan when endpoints change.

## Roles

| Role | How to get one |
|---|---|
| Public | No account |
| User | Register through the website form |
| Admin | Ask a developer for a seeded administrator (`🛠 needs dev`) |

## Test points

### 1. Registration

1. Public submits the registration form with a new email → an OTP email arrives.
2. Enter the OTP → signed in, profile shows `draft`.
3. `NEG` Submit the form with an already-registered email → the same "code sent"
   message, but the email says an account exists (no new account).
4. `NEG` Enter a wrong OTP five times → locked for 15 minutes.

### 2. Profile completion

5. Fill every required field and press Complete → status becomes `completed`.
6. `NEG` Press Complete with a field empty → the missing fields are highlighted.
7. Edit a detail right after completion → refused until the cooldown date shown.

### 3. Admin directory

8. Admin opens the user list → contact details are masked.
9. Admin opens a single user → full details shown (`🛠 needs dev` to confirm the
   PII-access audit row was written).
